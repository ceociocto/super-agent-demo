# 第二版操作演示（约 6–8 分钟）

## 准备

按 README 运行 `npm run executor:start`、`npm run executor:build`、`npm start`。打开 http://127.0.0.1:4317，在“运行环境”检查连接为在线。第一次初始化需要下载系统和基础镜像，提前准备。

## 1. 真正运行代码

任务 → 新建任务 → 代码修复 → 执行位置 Colima → 创建并执行。

在实时日志看 Linux 主机、任务和 run 标识、修复前测试失败、源码修改、修复后测试通过。切到产物与差异，核对 2通过/1失败 → 3通过/0失败及 diff，再点“验收通过”。下载产物。

说明一句即可：这是实际在 Linux 中运行的固定缺陷演练，不是任意代码问题的模型自主修复。

## 2. 使用自己的演示资料

知识资料 → 添加资料，输入以下非敏感示例，或导入自己的 .md/.txt：

```text
标题：Atlas 项目发布规程
发布前必须完成回归测试、负责人审阅、回滚方案和观察窗口确认。
负责人：林工；发布观察窗口为30分钟。
本周完成订单查询兼容修复；搜索索引更新等待验收。
风险：周五为发布冻结窗口。
下周计划：补齐搜索回归测试。
```

新建知识任务，只选择这份资料，提问“Atlas 发布需要哪些检查，观察多久？”查看来源与原文。再跟进“再展开一点”，检查仍保留原主题，并且产生新 run。

这里是真实的关键词检索和来源摘录，没有假装模型推理。查不到的知识会显示证据不足。

## 3. 资料报告

新建资料报告，选择刚上传的资料，要求整理本周进展和风险。查看实际原文汇总和来源；验收前不发布到外部平台。该任务的数据快照不会因后来编辑资料列表而改变。

## 4. 看历史、取消和失败

日志页的“执行记录”下拉可看上轮日志。任务 ID 不变，运行 ID 每次不同。

任务运行较快，取消/暂停可以在创建后马上操作；暂停中止当前容器，恢复会新建 run，不是从同一进程指令位置继续。完整竞态在自动化测试和真实执行集成脚本中验证。

若主机未启动，任务明确失败。恢复主机后点重试；当清理状态未确认时，不会启动另一个容器冒充续办。

事件记录折叠区可测试未授权发起者和重复事件。它们是本机模拟输入，不是公司平台身份认证。

## 5. 收尾

展示运行环境的 context 和镜像，说明 Mac 上协调、Linux VM 内执行。Colima仍共享同一台Mac，不能证明多机高可用。公司下一步是测试仓库、获准模型、知识权限和真实业务评测，详见架构文档。

演示后按需 `colima stop superagent-demo`；控制台终端 Ctrl+C。不要删除数据库来“恢复演示”，可用 README 的新数据库路径保留历史。
