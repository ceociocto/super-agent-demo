## 最重要的纠偏

用户记忆中的“真正代码运行端在独立服务器”抓住了**控制面和执行环境分离**这一核心，但视频没有要求代码必须放在云端的一台专用服务器。

原片 **12:45** 的第 14 页标题为“计算、状态、环境分离”，并明确写着 **“设计方向 · 本次未部署”**。图中包括：

1. 云端 Agent Loop；
2. 持久状态，说明“计算可替换，状态保留”；
3. 端点 daemon，持有“代码 / 工具链 / 本地环境”；
4. 端点离线时，依赖该环境的工作等待重连。

这表示 Agent 的推理与协调、数据库中的任务状态、实际运行代码的环境可以分开。执行环境可以是本地电脑、专用服务器、VM 或其他受控环境。视频展示的是架构方向，不是它本次运行实验已经部署成功的云端功能。

证据：[12:45 原尺寸画面](../work/local-team/media/environment-1245.png)。

因此，**在 Mac 上使用 Colima 的 Linux VM 模拟独立执行主机是合理的 PoC**。它验证跨 OS 环境派工、真实进程执行、日志回收、运行与任务状态分离。它仍然只有一台物理 Mac，关机和休眠会同时影响控制面与 VM，不能证明云端持续在线、多机高可用或真实网络故障恢复。

## Colima 配合本地演示的推荐边界

```text
浏览器操作台
    ↓ 本机回环 API
Mac 控制面：任务 / 授权 / 派工 / SQLite / 审批
    ↓ 指定 Docker context，经本机 Unix socket 调用
Colima Linux VM
    └─ 每次运行的受限容器 / 独立工作目录
       固定执行流程 → stdout/stderr → exit code → diff / 报告 / 测试结果
```

- 这是本机虚拟执行主机，不新增公网或局域网任意命令服务。
- 显式使用项目专属 Colima profile / Docker context，不切换用户全局默认 Docker context，不控制既有 OrbStack 工作负载。
- 控制面数据库和运行记录独立于执行容器；删除/重建容器不应删除任务及已归档产物。
- 只有明确选择的项目数据或经过准备的样例进入容器；不挂载整个用户 home、认证文件或宿主 Docker socket。
- 原型要展示真实 `exit code`、日志及产物，不以静态动画替代执行。演示用固定脚本时标明“真实运行的预置工作流”，不称为任意任务自主编程。
- 操作台的主要操作为新建任务、运行、停止、重试、查看日志、查看差异/报告和验收；架构理念进入文档。

## 最小验收集

1. 页面发起研发样例，Colima 内实际运行测试，并显示真实失败/通过、退出码和日志。
2. 同一任务再次运行保留 task ID、生成新 run ID；不会覆盖上一轮日志。
3. 停止运行能取消当前任务执行；迟到结果不覆盖新修订。
4. 关闭执行环境时不能报告成功；环境恢复后可明确重试。
5. 控制服务重启后还能读到任务、run、产物；未确认完成的旧运行应重新核实。
6. 知识/报告场景处理实际样例文件，引用到具体文件/记录；结果由真实程序产生。
7. 不把任何下载文档、日志里的指示提升为新授权。

### 与“独立主机”直接相关的语音时间窗

以下为结合原画面校正术语后的**内容摘要，不是逐字引文**：

- **12:35.440–12:48.680**：先分离运行 Agent Loop 的计算程序与需长期保存的会话/任务状态。计算容器可替换，数据库状态保留。
- **12:48.680–13:13.000**：再分离 Agent Loop 与实际代码/工具链环境。云端组织工作，开发机器运行轻量 daemon 执行命令并返回结果，可接入自己的机器，即 BYOM。
- **13:13.000–13:21.560**：机器离线时，依赖它的任务仍要等重连；云端在线不意味着离线电脑上的命令还能继续运行。
- **13:21.560–13:32.600**：完整云端 BYOM 不在本次本地验证范围，视频此处主要讨论设计方向。
- **13:45.480–14:14.880**：独立 Watchdog 检查异常和实际进展，尝试修复，但其模型判断、跨设备权限和凭证隐私仍有问题；该部分也未完整部署验证。

### 语音补充的两个实现细节

1. observe 不等于整个系统只读：它约束推断出来的主动任务，人的明确请求仍可能执行。不要把 UI 的“观察”开关描述为全局无副作用保证。
2. 持久化不只是最终结果落库：原型先记录外部操作意图，相关数据库事务提交后才执行；失败有退避重试。独立执行端的派工、接收结果和重启恢复应注意副作用去重，不能仅靠“任务状态写进 SQLite”宣称所有动作 exactly-once。
