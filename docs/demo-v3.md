# 六个真实演示用例

这些是现场演示方法，不是代码中预设的业务分支。可以临时更换仓库、目标或资料。所有场景都通过同一套 Router/Worker 与真实模型工具循环运行。视频对应点来自 [已有视频复核](video-analysis-v2.md)。

可直接复制的公开 issue 选题、完整问题转述与六段输入见 [具体任务清单](demo-catalog-v3.md)。

## 准备

按 README 设置模型并 `npm start`，先运行 `npm run test:model` 验证当前账号及端点。GitHub 演示先确保 `gh` 已登录；只在你有权限且愿意修改的仓库中提出写入请求。模型可能需要澄清，工具也可能真实失败，不能预设每次相同输出或时长。

网页左侧是任务，中间是总聊天，右侧是选定任务的执行过程、交付结果与任务对话。展开工具条目看参数和实际输出，切换执行记录查看历史 Run。

## 1. 自由 GitHub 任务：Router 与 Worker 分工

示例输入：

> 修复 https://github.com/OWNER/REPO/issues/NUMBER 描述的问题，补回归测试并提交草稿 PR。保留现有接口兼容性。

观察 Router 创建 Task，Worker 自行读 issue/源码、决定修改、运行测试并使用 gh 交付。实际代码工作在任务分支或工作副本进行。验证 PR 链接存在，测试输出来自真正执行的命令，不能把“建议 diff”称为已修改。

也可用不修改源码的 GitHub 任务展示，例如读取指定 issue、生成分析文件，或为已经推送的功能分支创建草稿 PR。实施期间的 GitHub 验收采用了创建本版本草稿 PR 的真实任务；它证明读取资料、调用 gh 和外部交付，不等于已经评测任意缺陷修复质量。

对应视频约 **02:30**。

## 2. 长任务不堵住新工作

先提交一个需要运行实际测试或数据处理的任务，再提出独立的资料整理任务。也可在同一条消息中明确提出两个独立目标。

观察两个 Task 的 Run 开始/结束时间重叠；总聊天仍可接收输入。`run_command` 在短暂等待后返回 jobId，日志写入文件；`wait_for_jobs` 等待作业完成或用户输入，避免持续调用模型轮询。程序禁止后台命令尚未结束时直接交付完成。

`npm run test:assistant` 用随机内容和真实文件/后台命令验证两个 Worker 的执行时间重叠，并核验产物内容。这里随机任务仅是验收输入，执行器没有针对它的业务分支。

对应视频约 **08:40**。

## 3. 补充要求进入原任务

在总聊天输入：

> 刚才的修复任务再加一个边界测试。

或在选定任务的详情中直接补充。观察 Task ID 保持不变，输入进入同一个 Worker 上下文。运行中的补充在模型步骤边界处理；已结束的任务会产生新 Run。另一项任务继续运行。

若“刚才那个”确实有歧义，助理应询问，不把猜测当成正确路由。停止清理期间收到的新跟进会等旧 Worker 退出后再续办。

对应视频约 **06:30**。

## 4. 长输出外置与按需回看

让 Worker 运行会生成较长输出的测试/诊断命令。观察工具结果中的 `logPath`、`nextOffset` 和 `hasMore`。完整日志保存于该任务 `.agent-logs`，模型只收到有上限的当前片段。

随后提出：

> 读取刚才保存的完整日志，定位指定失败项，引用真实行文说明原因。不要仅根据摘要猜测。

查看 Worker 的 `read_file` 分页调用。长会话在下一轮载入时归档，`read_history` 可按页访问历史消息和运行日志位置。此处是轻量引用恢复，不是无限模型上下文或完整的跨对象记忆网络。

对应视频约 **07:45**。

## 5. 停止与重启后继续同一任务

在实际命令运行时点“停止”，查看命令状态、Run 和已有文件。随后点“继续”或补充要求。也可停止服务并重新启动，再打开原任务。

观察 Task 和历史记录保留，未完成的执行标为中断；继续产生新 Run，Worker 获得核对既有文件、提交、PR 的指示。不能把“丢弃旧模型输出”当成撤销已发生的 GitHub 写入；也不保证进程从任意机器指令原地恢复。

用明确的文件或任务状态核验，不通过反复重放真实外部写操作来制造故障。对应视频 **05:20** 与 **12:45 的状态持久化部分**，没有实现云端 BYOM。

## 6. 网页与 MCP/CLI 接力

网页创建任务后，从本机终端查询：

```sh
node scripts/client.mjs tasks
node scripts/client.mjs followup task_ID '在原文件末尾补一段运行环境要求'
```

或由支持 MCP 的 Agent 调用 `get_task` / `followup_task`。观察网页显示同一个 Task 的新输入、修订与执行结果。下载文件核对新增内容，不能仅看“已接收”的提示。

实施期间已通过网页提交真实资料任务，再通过 stdio MCP 补充；同一 Task 的第二个 Run 更新了文件，浏览器下载文件与实际产物逐字一致。

对应视频约 **16:30 的任务中心思想**；多入口是本项目的扩展示例。
